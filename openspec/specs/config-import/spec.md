# config-import Specification

## Purpose

Импорт конфигурации заменяет пользователей, группы, сервисы и разрешения содержимым JSON-файла с устройства пользователя. Файл проверяется целиком до того, как что-то меняется. Тот же формат и та же проверка (`parseConfigFile` в `src/app/config-file.ts`) используются для экспорта и для копии конфигурации в `localStorage` (`src/app/storage.ts`).

## Requirements

### Requirement: Формат файла конфигурации

Файл конфигурации SHALL быть JSON-объектом с полями `version` (целое число) и списками `users`, `groups`, `services`, `permissions`. Экспорт SHALL записывать текущую версию формата `CONFIG_VERSION = 1` и все четыре списка. Конфигурация после экспорта и последующего импорта SHALL совпадать с исходной.

#### Scenario: Экспорт и обратный импорт

- **WHEN** учебная конфигурация экспортируется, а получившийся текст импортируется
- **THEN** результат равен `{ ok: true, config }` с исходной конфигурацией

#### Scenario: Версия в экспорте

- **WHEN** конфигурация экспортируется
- **THEN** поле `version` в файле равно `1` и является целым числом

#### Scenario: Пустая конфигурация

- **WHEN** импортируется файл, в котором все четыре списка пусты
- **THEN** файл принимается, и конфигурация состоит из четырёх пустых списков

### Requirement: Проверка корня и версии

Импорт SHALL отвергать файл с единственной ошибкой и без дальнейших проверок, если текст не разбирается как JSON, если корень не объект, если нет поля `version` с целым числом или если версия больше поддерживаемой. Версия меньше или равная поддерживаемой SHALL приниматься.

#### Scenario: Текст не JSON

- **WHEN** импортируется текст `{oops`
- **THEN** ошибки равны `["Файл не разбирается как JSON"]`

#### Scenario: Корень не объект

- **WHEN** импортируется `[]` или `null`
- **THEN** ошибки равны `["Файл должен содержать объект конфигурации"]`

#### Scenario: Нет версии или она не целое число

- **WHEN** в файле нет поля `version` или оно равно строке `"1"`
- **THEN** ошибки равны `["Нет поля version с целым числом"]`

#### Scenario: Версия новее поддерживаемой

- **WHEN** в файле `version` равно `2`
- **THEN** ошибки равны `["Версия формата 2 новее поддерживаемой 1"]`

### Requirement: Проверка формы списков и записей

Каждое из полей `users`, `groups`, `services`, `permissions` SHALL быть списком объектов. Поля `id` и `name` у пользователей, групп и сервисов SHALL быть непустыми строками, а `groupIds` пользователя — списком строк. Каждая ошибка SHALL указывать место в файле в виде `<key>[<индекс>]`.

#### Scenario: Отсутствует список

- **WHEN** в файле нет поля `groups`
- **THEN** ошибки равны `["Поле groups должно быть списком"]`

#### Scenario: Поле записи неправильного типа

- **WHEN** у второго пользователя `name` равно числу `5`
- **THEN** ошибки равны `["users[1]: поле name должно быть непустой строкой"]`

### Requirement: Проверка формы разрешений

`subject` разрешения SHALL быть объектом с `type`, равным `user` или `group`. Поля `id`, `serviceId` и `subject.id` разрешения SHALL быть непустыми строками.

#### Scenario: Неизвестный тип субъекта

- **WHEN** у первого разрешения `subject.type` равно `"team"`
- **THEN** ошибки равны `["permissions[0]: тип субъекта должен быть user или group"]`

### Requirement: Уникальность идентификаторов

Внутри каждого списка идентификаторы SHALL быть уникальными. Запись с уже встречавшимся в этом списке `id` SHALL давать ошибку `<key>[<индекс>]: идентификатор «<id>» уже занят`.

#### Scenario: Повтор идентификатора сервиса

- **WHEN** у второго сервиса `id` совпадает с `id` первого (`ledger`)
- **THEN** среди ошибок есть `services[1]: идентификатор «ledger» уже занят`

### Requirement: Ссылочная целостность

Если форма всех записей верна, импорт SHALL проверить ссылки: каждая группа из `groupIds` пользователя, субъект каждого разрешения (пользователь или группа) и сервис каждого разрешения SHALL существовать в файле. Индекс в тексте ошибки SHALL совпадать с позицией записи в файле. Если есть ошибки формы, проверка ссылок SHALL NOT выполняться.

#### Scenario: Разрешение на несуществующего пользователя

- **WHEN** у первого разрешения `subject.id` равно `nobody`
- **THEN** ошибки равны `["permissions[0]: нет пользователя «nobody»"]`

#### Scenario: Разрешение на несуществующую группу

- **WHEN** у второго разрешения `subject.id` равно `ghosts`
- **THEN** ошибки равны `["permissions[1]: нет группы «ghosts»"]`

#### Scenario: Разрешение на несуществующий сервис

- **WHEN** у третьего разрешения `serviceId` равно `vault`
- **THEN** ошибки равны `["permissions[2]: нет сервиса «vault»"]`

#### Scenario: Пользователь в несуществующей группе

- **WHEN** в `groupIds` первого пользователя добавлена группа `ghosts`
- **THEN** ошибки равны `["users[0]: нет группы «ghosts»"]`

### Requirement: Все ошибки файла собираются вместе

Начиная с проверки списков, импорт SHALL собирать все ошибки текущего этапа, а не останавливаться на первой.

#### Scenario: Две ошибки в одном файле

- **WHEN** у первого разрешения сервис `vault`, а у второго субъект — несуществующая группа `ghosts`
- **THEN** импорт возвращает две ошибки

### Requirement: Неизвестные поля игнорируются

Импорт SHALL принимать файл с полями, которых нет в формате, на любом уровне и SHALL NOT переносить их в конфигурацию. Новые поля формата добавляются как необязательные, версия растёт только при несовместимой правке.

#### Scenario: Файл с дополнительными полями

- **WHEN** в корень файла добавлено `exportedBy`, а в первого пользователя — `nickname`
- **THEN** файл принимается, и конфигурация равна исходной без этих полей

### Requirement: Импорт применяется целиком или не применяется вовсе

При успешной проверке импорт SHALL заменить конфигурацию целиком, сохранить её в `localStorage` под ключом `access-policy-simulator:config` в формате экспорта и показать сообщение «Конфигурация заменена». При любой ошибке конфигурация на экране и значение в `localStorage` MUST остаться прежними, а экран SHALL показать список ошибок под заголовком «Файл не принят, конфигурация осталась прежней».

#### Scenario: Корректный файл

- **WHEN** загружается корректный файл, в котором одно разрешение
- **THEN** в списке разрешений одна запись, а в `localStorage` лежит экспорт импортированной конфигурации

#### Scenario: Файл с ошибкой

- **WHEN** загружается файл, где у первого разрешения сервис `vault`
- **THEN** экран показывает ошибку `permissions[0]: нет сервиса «vault»`, число разрешений не изменилось, а `localStorage` по-прежнему пуст

#### Scenario: Корректный файл после ошибочного

- **WHEN** после отвергнутого файла `{oops` загружается корректный файл
- **THEN** появляется статус успешного импорта, а сообщение об ошибке исчезает

### Requirement: Загрузка сохранённой конфигурации

При запуске приложение SHALL читать конфигурацию из `localStorage` той же проверкой, что и импорт. Если сохранённого значения нет, оно не проходит проверку или хранилище недоступно, приложение SHALL использовать учебные данные. Ошибка записи в хранилище SHALL NOT прерывать работу в текущей вкладке.

#### Scenario: Ничего не сохранено

- **WHEN** в хранилище нет значения под ключом приложения
- **THEN** загружаются учебные данные

#### Scenario: Сохранённое значение повреждено

- **WHEN** под ключом приложения лежит `{oops`
- **THEN** загружаются учебные данные

#### Scenario: Сохранённое значение нарушает ссылочную целостность

- **WHEN** под ключом лежит конфигурация, в которой разрешения ссылаются на отсутствующие сервисы
- **THEN** загружаются учебные данные
