# access-calculation Specification

## Purpose

Расчёт доступа отвечает, есть ли у сотрудника доступ к сервису, и называет разрешения, на которых этот доступ держится. Расчёт выполняет единственный модуль `src/domain/access.ts` (`calculateAccess`), и все экраны берут результат из него. На вход он получает конфигурацию (пользователи, группы, сервисы, разрешения) и запрос: `userId`, `serviceId` и момент расчёта `at`. На выходе — `{ granted, sources }`.

## Requirements

### Requirement: Доступ по прямому разрешению

Расчёт SHALL считать источником доступа каждое разрешение, у которого субъект — пользователь (`subject.type = "user"`) с идентификатором из запроса, а `serviceId` совпадает с сервисом из запроса. Такой источник SHALL иметь вид `{ kind: "direct", permissionId }`.

#### Scenario: Пользователь с прямым разрешением

- **WHEN** у пользователя `boris` есть разрешение `p1` на сервис `ledger` и запрашивается доступ `boris` к `ledger`
- **THEN** `granted` равно `true`, а `sources` равно `[{ kind: "direct", permissionId: "p1" }]`

### Requirement: Доступ через разрешение группы

Расчёт SHALL считать источником доступа каждое разрешение на запрошенный сервис, у которого субъект — группа (`subject.type = "group"`), входящая в `groupIds` пользователя. Такой источник SHALL иметь вид `{ kind: "group", permissionId, groupId }`, где `groupId` — группа из разрешения.

#### Scenario: Пользователь получает доступ через свою группу

- **WHEN** `boris` состоит в группе `support`, у группы `support` есть разрешение `p3` на сервис `mail`, и запрашивается доступ `boris` к `mail`
- **THEN** `granted` равно `true`, а `sources` равно `[{ kind: "group", permissionId: "p3", groupId: "support" }]`

#### Scenario: Пользователь в нескольких группах

- **WHEN** `anna` состоит в группах `accounting` и `support`, и из её групп разрешение на сервис `ledger` (`p2`) есть только у `accounting`, а прямого разрешения на `ledger` у неё нет
- **THEN** `sources` равно `[{ kind: "group", permissionId: "p2", groupId: "accounting" }]`

### Requirement: Учитываются все источники в фиксированном порядке

Расчёт SHALL возвращать все найденные источники, а не первый подходящий. Прямые источники SHALL идти первыми, за ними — групповые. Внутри каждой из двух частей источники SHALL следовать в порядке разрешений в конфигурации.

#### Scenario: Прямой и групповой источник одновременно

- **WHEN** у `anna` есть прямое разрешение `p4` на `mail`, и её группа `support` имеет разрешение `p3` на `mail`, причём в конфигурации `p3` стоит раньше `p4`
- **THEN** `sources` равно `[{ kind: "direct", permissionId: "p4" }, { kind: "group", permissionId: "p3", groupId: "support" }]`

### Requirement: Доступ есть тогда и только тогда, когда есть источник

`granted` SHALL быть `true` ровно тогда, когда список `sources` не пуст. Если подходящих разрешений нет, расчёт SHALL вернуть `{ granted: false, sources: [] }`.

#### Scenario: Пользователь без разрешений

- **WHEN** `vera` не состоит ни в одной группе и не имеет прямых разрешений, и запрашивается её доступ к `ledger`
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Учитываются только разрешения на запрошенный сервис и группы пользователя

Расчёт MUST NOT учитывать разрешения на другие сервисы, разрешения других пользователей и разрешения групп, в которых пользователь не состоит.

#### Scenario: Сервис без разрешений

- **WHEN** запрашивается доступ `boris` к сервису `unknown`, на который в конфигурации нет разрешений
- **THEN** `granted` равно `false`

#### Scenario: Разрешение чужой группы

- **WHEN** `boris` состоит только в `support`, а на `ledger` есть разрешение `p2` группы `accounting`
- **THEN** `p2` не попадает в `sources` для `boris` и `ledger`

### Requirement: Момент расчёта передаётся явно

Расчёт SHALL получать момент расчёта параметром `at` и MUST NOT читать системные часы (`Date.now()`, `new Date()` без аргументов). Пока в модели нет данных, зависящих от времени, результат SHALL совпадать для любого значения `at`.

#### Scenario: Один и тот же ответ в разные моменты

- **WHEN** доступ `boris` к `ledger` рассчитывается с `at = 2020-01-01T00:00:00Z` и с `at = 2040-01-01T00:00:00Z`
- **THEN** оба результата равны
